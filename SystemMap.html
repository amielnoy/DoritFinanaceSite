1 · Delivery

The same commit is built twice by two hosts with different commands, which is the one piece of the picture that surprises everybody: the production copy a visitor gets and the copy CI tests are not byte-identical.

Not in the pipeline

npx base44 agents push and npx base44 functions deploy are manual steps. CI never performs either, so a merged change to a prompt in base44/agents/ or a function in base44/functions/ is in the repository and not yet running. Every green build on a prompt change means the file is correct, not that it is live.

Five components and five page modules nothing can reach

The whole booking/ directory — CalendlyBooking, GoogleCalendarBooking, OutlookCalendarBooking — has no importer. That is the residue of a real decision: booking a first meeting stopped being a separate errand from being interviewed for one, and the interview now closes the meeting itself. ReviewsWidget and QuickShare are orphaned too.

Among the pages, Register.jsx, ForgotPassword.jsx, ResetPassword.jsx and OAuthConsent.jsx are in no route. And Login.tsx and Login.jsx both exist, so @/pages/Login is ambiguous — Vite's default extension order puts .jsx ahead of .tsx, which means the JavaScript copy is the one that ships and the TypeScript copy is dead code that still typechecks. Worth resolving deliberately rather than by resolver order.

3 · Ports and adapters — the seam

No component imports a backend SDK. Eight interfaces in src/services/ports.ts stand between the app and whoever is serving it, and src/services/index.ts is the single place that decides which adapter satisfies each one. Two properties nobody typed by hand, and both have broken production

allow_anonymous_access must be true or every conversation on a public page returns 401 — which it did, for ten days, while the visitor saw only "I couldn't send that just now". memory_config.enabled must be false, because the platform default shares a global half between all users and every one of these chats is reached by anonymous strangers. Both flags were written by a Builder regeneration, not by a person, and the contract suite now pins the whole configuration for that reason.

5 · Where the data actually lives

Two stores, deliberately. Base44 entities are the authority today; every write is mirrored into Supabase so that the second store is warm and current before any read is moved across. A mirror failure is logged and swallowed — the authority must not fail because the copy did.

7 · What holds it together

scripts/run-tests.sh runs nine in order and stops at the first red one: lint, typecheck, unit, component, contract, integration, security, build, e2e. Two more sit outside it — the evals, which need credentials, and the report. The split that matters is the last one: a contract test proves a prompt says something; only an eval shows the model does it.
